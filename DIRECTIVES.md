# DIRECTIVES

Durable rules of thumb for how we work on this project.

## How to use
- Add concise directives that remain true over time.
- Prefer principles over implementation details.
- When a directive conflicts with a tactical plan, update the plan (or explicitly note the exception and why).

## Directives
- Favor simple solutions that solve the current problem.
- Grow scope through iteration rather than upfront complexity.
- Prefer small, reversible changes over large rewrites.
- Prefer clear, explicit names over abbreviations.
- Keep docs skimmable; remove redundancy.
- Update `ANCHOR.md` when product intent, UX, or scope changes.
- Dev environment is Linux via Dev Container; do not rely on host-installed toolchains (applies to humans and coding assistants).
